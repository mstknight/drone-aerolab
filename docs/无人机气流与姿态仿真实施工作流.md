# 无人机气流环境与飞行姿态调整：实施工作流

## 1. 目标与首版范围

将车辆风洞实验室改造成无人机飞行实验室。用户可以选择气流环境、调节风速与风向，实时观察三维无人机的位置、姿态、气流分布，以及控制器如何通过四个电机的差动推力抵抗扰动。

首版默认采用 X 型四旋翼，以定点悬停抗风为核心任务；后续扩展航点飞行、复杂建筑环境和真实飞控接入。此处“实时可观测”默认指仿真风场的实时可视化，不表示已接入真实风速传感器。

完整闭环：实验配置 → 风场采样 → 控制器与电机响应 → 六自由度动力学积分 → 三维姿态与气流显示 → 指标记录 → 对比与回放。

## 2. 现有项目如何复用

| 当前模块 | 改造方式 |
| --- | --- |
| React + Vite 页面 | 保留技术栈，改成飞行实验、实验对比和 CFD 数据页面 |
| `src/main.js` 的 Three.js 场景 | 拆分场景、模型、风场、仿真循环和交互；替换车辆模型与固定车辆逻辑 |
| GLB 加载、相机、灯光 | 保留加载能力，新增真实尺度、重心与四个旋翼节点配置 |
| 车辆解析流线 | 替换为三维时变风速场；不能继续按车辆包围盒生成无人机气流 |
| `src/FieldViewer.jsx` | 复用色标与场数据显示思路，移除长方体几何、固定截面和坐标假设 |
| `src/CfdPanel.jsx` 与 `cfd/` | 复用任务管理、结果导出和审计；无人机几何、网格、边界与旋翼模型单独建设 |

依据当前代码与说明，项目已有视觉演示及稳态长方体 CFD 流程，尚无无人机动力学和闭环控制。已有计算不能充当无人机验证数据。

## 3. 分阶段执行

### 阶段一：实验定义与接口约定

工作：
- 定义机型参数：质量、惯性张量、机臂长度、旋翼半径、最大推力、推力/反扭矩系数和电机响应时间。无实测参数时使用明确标注的演示参数。
- 统一米、秒、千克、弧度等内部单位，界面可显示角度。
- 定义右手世界坐标与机体坐标、旋翼编号和旋转方向。建议仿真采用 Z 向上，渲染层转换至 Three.js 的 Y 向上；导入 CFD 数据也通过同一转换层。
- 定义状态：位置、速度、姿态四元数、角速度、电机转速、仿真时间。
- 定义风场接口 `sampleVelocity(position, time)` 和控制器接口 `step(state, target, dt)`。

产出：实验配置、坐标约定、数据结构、首批验收工况。

验收：三轴正方向、力矩方向及单位转换一致；确定首版悬停目标与适用风速范围，避免直接沿用汽车的 0–200 km/h 滑块。

### 阶段二：无人机与环境三维建模

工作：
- 先用程序化几何创建机身、四个机臂、独立旋翼与起落架；保留导入精细 GLB 的入口。
- 为精细模型绑定重心、旋翼中心和朝向，不沿用车辆最长边统一缩放为 4.7 的处理。
- 建立风洞测试区和开放空域两类基础场景，提供网格、尺度、悬停目标、轨迹和机体轴。
- 提供自由观察、跟随、俯视和侧视视角。
- 视觉模型与质量、惯性、碰撞代理分离；GLB 外观不自动产生可信气动参数。

产出：可旋转观察、可独立控制四旋翼节点的无人机场景。

验收：尺寸与旋翼位置匹配配置，姿态三轴方向正确。障碍物只有在同步接入风场模型后，才表现相应绕流影响。

### 阶段三：实时风场及气流可视化

工作：
- 按顺序实现无风、恒定侧风、平滑阵风、周期变化风、垂直气流和带固定随机种子的时空相关扰动。
- 风场由基础来流、阵风和局部扰动组合；避免使用逐帧独立随机数冒充连续湍流。
- 在同一风场接口上实现粒子平流、速度箭头、切片云图和空间探针。
- 气流颜色表达速度大小并提供 m/s 色标；支持密度、透明度和显示范围调节。
- 允许显示世界坐标风速，以及无人机所感受到的相对气流，两者明确区分。
- 旋翼下洗可先做近似显示，但需独立开关并标明来源。若参与动力学，必须防止与旋翼推力模型重复计算。

产出：可调整参数、可在任意位置读取风速的三维动态风场。

验收：粒子、探针、箭头及机体受风采样共享数据源；无风时环境风速归零；时变风场中的粒子轨迹称为迹线，瞬时流线需另行积分，不能混用概念。

### 阶段四：六自由度飞行动力学

工作：
- 模拟重力、四旋翼推力、旋翼反扭矩、机臂力矩以及简化气动阻力。
- 由局部风速与机体运动计算相对气流，并转换到需要的参考系。采样机臂或旋翼位置时，计入旋转运动造成的局部速度。
- 使用四元数积分姿态并归一化；欧拉角仅用于仪表显示。
- 加入电机转速范围、推力饱和与响应滞后。
- 采用固定仿真步长并与渲染解耦；可从 200 Hz 仿真、目标 60 fps 渲染起步，最终频率以稳定性和性能测试决定。
- 处理暂停、单步、重置、地面接触与出界。第一版地面接触可采用终止实验规则，无需先实现复杂接触动力学。

产出：无人机运动由受力和力矩驱动的仿真内核。

验收：无控制时重力方向正确；总推力等于重力时具备悬停平衡；差动推力引起预期旋转；改变渲染帧率不改变同一实验的物理结果。

### 阶段五：抗风姿态控制

工作：
- 采用位置 → 速度 → 目标姿态/总推力 → 姿态 → 角速度 → 电机分配的串级控制。
- 先打通角速度和姿态内环，再加入高度、水平速度及位置外环。
- 增加积分限幅、抗饱和、倾角限制及最大推力限制。
- 提供固定电机输入、姿态稳定、定点悬停三种模式。纯姿态稳定不承诺抵消横向位置漂移。
- 支持控制参数调节，并显示目标/实际姿态、位置误差和四个电机输出。

产出：横风下自动倾斜、通过推力水平分量抵抗扰动的悬停闭环。

验收：无风悬停稳定；额定能力范围内阵风后能够回到目标附近；超过能力时如实显示漂移与输出饱和。不得通过直接锁定位置或插值到目标角度实现假稳定。

### 阶段六：实验控制台、记录与比较

工作：
- 左侧放环境、机型、任务和控制器参数；中央为三维场景；右侧显示姿态、速度、高度、误差和电机输出；底部显示曲线与回放时间轴。
- 提供开始、暂停、单步、重置、保存实验、载入预设及导出 CSV/JSON。
- 同步记录状态、目标、风场参数、随机种子、控制器参数、版本和时间戳。
- 支持同一风场下的模式/参数对比，展示最大位置偏差、位置均方根误差、最大倾角、恢复时间及饱和时长。
- 恢复时间需预先定义误差阈值与持续稳定窗口。回放优先使用记录状态；重新仿真需保留配置与版本以支持复现。

产出：可完成“选工况—调参数—运行—观察—对比—导出”的实验页面。

验收：曲线、场景与探针时间一致；固定种子可重复生成扰动；记录能重现一次完整实验。

### 阶段七：离线 CFD 与更高精度验证

工作：
- 准备独立、封闭、尺度明确的无人机计算几何与网格；精细显示模型不直接视为可求解几何。
- 先计算固定姿态机体在不同来流与攻角下的气动载荷，建立适用范围明确的气动力/力矩查询表。
- 按需求逐步引入执行器盘、MRF 或瞬态旋翼模型；选择前明确所需时间分辨率和计算预算。
- 扩展现有场数据格式，支持三维速度、坐标、单位、时间及有效域，实时模块对预计算结果采样或插值，域外情况显式处理。
- 对网格、时间步长、计算域、载荷收敛及可用基准数据进行验证；需要时再接入 PX4/ArduPilot SITL 比较控制行为。

产出：用于校准实时模型的离线数据，以及明确的精度与适用范围说明。

验收：实时近似、预计算场回放与实际在线求解状态明确区分。稳态 CFD 场本身不包含真实瞬态阵风，更不能把浏览器画面每帧更新称为每帧重算 CFD。

## 4. 推荐代码分层

```text
src/
  scene/           场景、相机、无人机模型、坐标转换
  simulation/      状态、动力学、电机、固定步长循环
  control/         PID、串级控制、电机分配
  wind/            风场接口、阵风、扰动、CFD 数据适配
  visualization/   粒子、箭头、切片、轨迹、探针
  components/      实验控制台、姿态仪、曲线、回放
  experiments/     预设、记录、导出、评价指标
cfd/               保留计算基础设施，新增无人机专属案例
```

渲染读取仿真状态，不反向修改物理状态。仿真与气流可视化读取同一版本的风场配置。性能需要时将动力学和数据处理移入 Web Worker，主线程保留交互和渲染。

## 5. 里程碑与交付顺序

| 里程碑 | 范围 | 完成标志 |
| --- | --- | --- |
| M1：场景与风场 | 阶段一至三 | 无人机模型、真实尺度、侧风/阵风、箭头/粒子/探针联动 |
| M2：最小可用实验 | 阶段四至六的核心功能 | 无风悬停、阵风抗扰、控制模式对比、曲线及导出 |
| M3：复杂环境 | 障碍物风场、航点、局部扰动、更完整回放 | 场景几何与风场模型对应，跨工况可复现比较 |
| M4：精度提升 | 阶段七 | 无人机专属 CFD 数据与实时模型校准报告 |

首个端到端演示固定为：无人机悬停 → 施加右侧阵风 → 观察风场和机体偏移 → 控制器调整各电机推力 → 机体倾斜并恢复位置 → 回放曲线，与仅姿态稳定模式比较。

每个里程碑再执行构建、对应物理/控制检查与浏览器交互检查；性能目标以目标设备上的实测结果为准。本工作流为改造计划，尚未实施上述新增功能。
